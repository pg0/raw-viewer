# RAW Viewer

Browser-based RAW photo viewer and editor. Single-page app (`index.html`), vanilla JS, WebGL2 pipeline. No build step, no backend.

By **Patrick Gawron** ([pg0](https://github.com/pg0)) - <https://github.com/pg0/raw-viewer>
Live demo: <https://pg0.github.io/raw-viewer/>

## Features
- RAW decode (LibRaw + dcraw), plus JPEG / PNG / WebP / BMP / GIF / HEIC / TIFF (uncompressed, LZW, PackBits, ZIP; 8- and 16-bit, via UTIF)
- Real-time WebGL2 adjustments: exposure, contrast, highlights/shadows, white balance, saturation, vibrance, and film grain - additive, luma-weighted, band-limited (Perlin gradient noise + particle shaping, same math as the FilmGrain DCTL), image-anchored so it bakes into the export. Grain controls are minimal and WYSIWYG: pick a film stock (Super 8 / 16mm / 35mm / 65mm / Custom) and it writes the visible Intensity + Grain size sliders to that format's real values (no hidden multiplier); editing a slider by hand flips it to Custom. Grain size is resolution-normalized (scales with image height / 1080p) so the look is identical at any resolution, and it starts off (Custom, intensity 0)
- Two `.cube` LUT slots (converter + style) with per-slot intensity
- Overlays: stack images, SVGs, text, or emoji (grain, film strip, light leaks, dust, stickers, captions) blended over the photo. Add via the panel buttons (+ Image / + Text / + Emoji) or by dropping an image onto the panel. Per overlay: blend mode (Normal / Screen / Multiply / Add), opacity, keep-aspect (contain-fit vs stretch), tiling, scale/zoom (0.1x - 12x), X/Y offset, and an optional alpha (chroma-key) colour to knock a colour out to transparent. Select an overlay and drag it on the photo to reposition it, drag the grip handle in the list to reorder layers, and double-click a text overlay to edit it. An "Apply effects to overlays" toggle at the top of the panel grades the overlays together with the photo (LUT, grain, exposure and the rest land on the overlays too). Overlays track crop/rotation and bake into the export
- Free-angle rotation (type any degree, or 90&deg; CW/CCW icons), crop with aspect presets (Free / 1:1 / 5:4 / 16:9 / 20:9) and a Portrait/Landscape orientation toggle, zoom/pan
- Histogram, per-group show/hide (A/B compare), JPEG export at full resolution
- Face/Smile Detect: local face detection (MediaPipe FaceLandmarker WASM, vendored in `face/`, lazy-loaded; opening the panel or loading a new photo while it is open runs detection automatically, and dragging a morph slider re-analyzes the edited result live - the smile % and eye-openness % update to what the warp actually achieved). The panel header has the same eye toggle as the adjustment groups, bypassing the whole face bake for an A/B look. Reports per face whether the person smiles (mouthSmile blendshapes), whether the eyes are open (landmark eye-aspect-ratio) and a coarse expression bucket (happy / neutral / surprised / angry / sad, from the same blendshapes - a Duchenne grin fires browDown hard, so a high smile outranks it, and "angry" additionally requires non-squinting eyes since browDown + eyeSquint is a sun squint or a laugh; the brow-driven labels stick to the original detection, because re-detecting the baked morph reads absurd brow values on small faces), plus a summary ("2 of 3 smiling - closed eyes: face 2"). A group smile score sits in the panel header as counts - "2🙂 1😐", smiling = mouthSmile >= 30% - and follows the live re-analysis, so pulling a Smile slider moves a face from 😐 to 🙂 (a count says who the group shot is waiting on; an averaged emoji hid one flat face behind three grins). Detection runs at a low confidence bar (0.15) so small faces in group shots are found, then junk is dropped by a nose-distance dedup (duplicate detections of one face) and a minimum inter-ocular size floor. Clicking a face selects it; its × badge or Delete removes a wrong detection. Next to "Detect faces" sits "Detect (tiled)" - re-detection in 4 overlapping 2x-zoomed tiles, because the detector only proposes faces above a minimum size relative to the frame (lowering the confidence threshold finds nothing extra in group shots; zooming does). An "Other detections" section adds debug info: input size, per-pass raw counts, what the filters removed, and per-face inter-ocular px / smile % / eye-aspect-ratios. It also exposes the rest of the MediaPipe vision suite as toggleable overlays, each loading its model on first use: **Objects** (EfficientDet-Lite0 boxes with class and score - always run tiled like the face deep scan, since the model squashes its input to 320 px: on a 5-person test shot the full frame alone found 4 people, the tiled run 5 plus an umbrella; boxes clipped by a tile border are dropped and the rest merged by same-class NMS; click a box to select it, then its × badge or Delete removes it and its keyword; double-click opens an inline rename field, which is usually what makes a keyword worth writing - "person" becomes a name), **Scene** (EfficientNet-Lite0 ImageNet labels for the whole frame; useful for objects, animals and places, close to useless on people shots because ImageNet-1k has no person classes - only labels above 15% become keywords, so those photos simply contribute none), **Segments** (selfie-multiclass segmentation tinting hair / skin / face / clothes / other), **Touch** (prompted segmentation with MediaPipe's MagicTouch model: click any object on the photo and it is masked and outlined - unlike Segments this is not limited to a fixed class list; ctrl-click (cmd on macOS) adds another object to the selection, shift-click cuts one out again, a plain click starts over; the picked object comes back as category 0, everything else as 1), **Pose** (33 body landmarks, up to 6 people) and **Hands** (21 landmarks per hand, up to 8). Pose and Hands run well below MediaPipe's 0.5 default confidences (0.2 / 0.15) on purpose - at the defaults a group shot returns only the largest, most frontal person (measured on a 4-person photo: 0.4 gave 3 poses, 0.2 all 4; hands 0.3 gave 2, 0.15 gave 3). The counts and labels are summarised as text under the buttons. Once objects are detected a "to EXIF" button appears: it stages the deduplicated class list as keywords (shown in the Metadata panel), and the next JPEG export gets them written in - `canvas.toBlob()` produces a bare JPEG, so two APP1 segments are spliced in behind the JFIF header, EXIF (ImageDescription + XPKeywords, the field Windows Explorer shows as "Tags") and XMP (`dc:subject`, what Lightroom and Bridge read). These need no detected face, so they work on any photo. A "Child protect" row anonymizes detected faces in four ways: an eye bar (click the button again to flip it black/white), a colour-emoji smiley over the whole face (trimmed to its opaque bounds so it actually covers the face oval; double-click a smiley on the photo to pick a different emoji for that person), a mosaic, or a blur. It works per person: with a face selected the buttons write only that face's mode (the row label says which), with nothing selected they set the default for everyone and drop the per-face overrides - so a group shot can have one blurred kid and four untouched adults. The bar is centred on the eye openings rather than on the iris landmarks, which track the pupil and drop the bar off the eyes on a downward gaze; its height comes from how far the lids reach off the eye line, so it covers both eyes on a tilted head. Mosaic and blur clip to the face-mesh silhouette (the FACEMESH_FACE_OVAL ring, smoothed and grown 6%), not to a circle that would eat background. Bar and smiley follow head roll. All of it is drawn into the face bake pass, not onto the screen overlay, so it survives the JPEG export (the layer is built on a 2D canvas capped at 3072 px and linearized in the shader, since the bake target is linear light; mosaic and blur read the ungraded base, so the grade still applies on top of a pixelated face rather than being baked into it). A four-way mask overlay (None / Box / Mask / Eyes+mouth, back to Box for every new photo) draws per face either a numbered box, the full landmark tessellation, or the eye rings (green = open, red = closed) + iris rings with centre dots + lip outline; numbers match the status list and sliders, and the overlay tracks the smile warp (lip outlines follow the reshaped mouth). Clicking a face on the photo (or its label in the panel) selects it: the box and its number turn amber and the matching slider block is highlighted and bold, so it is unambiguous which sliders belong to whom in a group shot. Clicking it again, or clicking empty space, clears the selection. Three solver buttons sit at the top of the panel, right under the status lines. **Auto** does not guess a slider value, it closes the loop: it sets a value, bakes it, re-measures the result with MediaPipe and corrects, until each face reaches the same *measured* smile (~55% mouthSmile) - so a mouth that reacts strongly gets a small value and a stiff one a large value, and faces already smiling past the target are left alone. **Neutral** closes the mouth but keeps a hint of a smile (~25%); **Model** relaxes it all the way to a flat look (~5%), also closed. The mouth close works in landmark pairs: each inner-lip point meets its across-mouth partner, but not halfway - opening a mouth is mandible depression, the upper lip barely moves, so the contact line sits just under the upper lip (12% of the gap; a midpoint meet dragged the whole mouth visibly downward), and it is pulled hard toward the corner-to-corner chord with a centre dip - the dip is per button (Neutral a clear hint of a smile, Model near straight; it IS their visible difference, since the damped negative-smile term barely moves a closed mouth): the raw upper contour of an open grin arches up in the middle, and a contact line that keeps that arch reads :( (centre above the corners) - every solver button is a smile variant, flat is the worst allowed outcome, so the corners the smile term lifts stay the high points. The pairs overshoot the meet by 5%, overlapping the contours slightly, so no sliver of teeth survives *between* landmark pairs (the warp is linear between pairs, real lip edges bow). Closing a grin also lets the lifted cheek down in proportion to how far the mouth was open - the apple of the cheek in the photo was raised by the original smile, which the mouth warp alone never touches. The outer ring rides its inner neighbour the full way, so the vermilion translates rigidly and the teeth collapse behind the meeting lips instead of being squashed into a band. Whatever thin remnant survives texture filtering is covered by a painted contact shadow along the seam - the pair-midpoint line is known exactly, so no teeth detection is needed; the colour is sampled from the lower lip and darkened per channel toward red (a uniform darkening desaturated pale lips into a gray drawn-on line - the real inter-lip shadow is darker AND redder; and a translucent stroke ghosted bright teeth through as light specks, so the stroke is fully opaque, narrow and blurred), and it fades out with the pre-close aperture - a mouth that was already closed collapses nothing, so nothing is painted there. The sensor replays the exact detection tile that found each face; a full-frame re-detect is useless as a sensor, because the faces in a photo that needed the tiled scan are invisible to it (every reading silently kept the value from the original detection), and a fresh crop around the face is not reliable either - measured here, a face found by a 0.25 tile was missed by its own 1.8x crop at every scale from 1x to 3x. A face the detector loses mid-solve keeps the analytic estimate instead of a stale reading. Both buttons follow the same selection rule as Child protect: a selected face is the only one edited. Under "Smile parameters" (collapsed by default, together with the Closed Eye Photo controls) each detected face gets five sliders (Smile -100..150; Mouth width 70-100% and Mouth height 70-130%, which scale the lips along and across their axis; Mouth pos Y -20..20% shifting the whole mouth along the face axis for a close result that sits a touch too low or high; and Brows -50..100, a raise where the upper lids follow at ~40% so the eyes open with the brows and the look lifts - the range is calibrated so the full slider stays natural and the brows never leave the eyes behind, while a small negative lowers them toward a frown) that reshape that mouth with a piecewise-affine warp: outer + inner lip rings are Delaunay-triangulated together with a pinned anchor ring (subnasale/nostrils, chin, jaw, nose, cheekbones) and drawn as displaced textured GPU triangles - displacement is exactly zero outside the anchor ring, so nothing but the mouth region can move (the earlier MLS field always bled into the rest of the face). Smile targets follow zygomaticus kinematics: corners travel supero-laterally, the smile reading mostly from corner curvature rather than width (a larger lateral share made the lips look stretched), the upper lip elevates slightly, cheeks follow at about a third; on a turned head the foreshortened far side is damped, since full excursion there curls the lip toward the camera. Negative values are not the mirrored smile - relaxing lets the zygomaticus go rather than pulling inward, so the lateral and rise coefficients are damped and the mouth-close term takes over. "Closed Eye Photo" takes a second shot of the same person(s) - faces matched left-to-right after the same dedup/size filtering - and replaces closed eyes with the donor's open ones (per-eye similarity transform + feathered ellipse blend in linear light, luma-gain matched); the info line names the faces it applies to, and Eye size / Eye direction X/Y sliders tweak the donor content (scale around the eye center, shift in the rotated eye frame) when the 2D auto-fit can't match a 3D gaze difference. Runs as a pre-grade pass, so denoise/LUT/grain apply on top and it bakes into the export. Needs the server (or the live site) - the WASM engine can't load from `file://`
- Double-click (or double-tap on touch) any slider or its label to reset it
- "Full resolution" toggle appears only for RAW files (nothing to re-decode behind a JPEG/PNG)
- Always-visible top bar (title + Open / Save) and a mobile-friendly layout: photo pinned on top, controls scroll below, pinch-to-zoom, vertical drag scrolls the panel (doesn't nudge sliders), and a button to switch the photo pane between 2/3 and 1/3 of the screen

## Two ways to run

### 1. Quick (`file://`) - double-click `index.html`
Works for standard images, `.cube` LUTs, and RAW from cameras the bundled **dcraw 9.26** can decode. For newer RAW it cannot decode, it shows the embedded JPEG preview. LibRaw is unavailable here (service workers / module workers don't run on `file://`).

### 2. Full decoder - run `serve.cmd` (or deploy to Pages)
Starts a local server on `http://localhost:8791/` and enables the **LibRaw 0.22.1** decoder (`libraw/`).

```
serve.cmd            # or: python serve.py [port]   (Python 3)
```

LibRaw is a pthreads WebAssembly build (shared memory), so the page must be **cross-origin isolated** (`Cross-Origin-Opener-Policy: same-origin` + `Cross-Origin-Embedder-Policy: require-corp`). `serve.py` sends those headers - a plain `python -m http.server` will not work. On GitHub Pages (which can't set headers) a bundled `coi-serviceworker.js` shim provides the same isolation client-side.

## Supported RAW formats
The extension list many tools quote is **dcraw 9.26's** set (ARW, CR2, NEF, DNG, RAF, ORF, RW2, PEF, SRW, SR2, KDC, DCR, MRW, 3FR, ERF, MEF, MOS, X3F, ...) - and it's frozen at ~2016, so it misses recent bodies.

With the LibRaw path enabled (server / Pages) support jumps to **LibRaw 0.22.1's** full modern list: 1000+ cameras including **Sony ZV-E1**, Canon **CR3**, newer lossless-compressed ARW, current DNG, GoPro GPR, Phase One IIQ, and more. dcraw remains only as the offline (`file://`) fallback.

### Decoder cascade
For a RAW file the app tries, in order:
1. **LibRaw** (server/Pages) - full decode of virtually any modern RAW.
2. **dcraw** (also `file://`) - older cameras.
3. **Embedded JPEG** - last resort so the file stays viewable / croppable / exportable.

## Supporter key

RAW Viewer is free and stays free - no login, no paywall, no tracking. If it
saves you time, there's an optional "supporter key" honor-system nudge: the
♥ Support chip in the top bar opens a small modal explaining the deal, with
a link to <https://patrickgawron.com/support>.

Unlock works three ways:
- Paste a key into the modal's input and hit Unlock.
- Open the app with `?key=<key>` or `#key=<key>` in the URL (the key is
  saved to `localStorage` and stripped from the URL automatically).
- Nothing to do on repeat visits - a previously unlocked key is remembered.

Once unlocked, the chip becomes "♥ Thanks, `<name>`" (hover for the
supporter-since date), and the settings-preset row in the sidebar grows from
**3 slots to 9** - the app's only supporter perk. Nothing is removed or
gated for non-supporters; the tool stays fully functional either way.

Verification is 100% local: ECDSA P-256 + SHA-256 via the browser's
`crypto.subtle`, no network call, no server. Keys are issued with the
[`supporter-key`](../supporter-key) CLI - see that project for the format
spec, the issuing workflow, and how to embed the same verify snippet in
another tool.
